# Red Parcel – Backend Integration Guide

This guide shows how to move from the current **simulated prototype** to a **real working system**.

---

## Current State vs Target State

| Feature                    | Current Prototype      | Target (Real)                     |
|---------------------------|------------------------|-----------------------------------|
| Bus location              | JS timer simulation    | Real GPS from driver phone        |
| ETA                       | Fake countdown         | Distance + traffic based          |
| Tracking ID               | Generated in UI        | Generated by backend              |
| Status flow               | Local only             | Stored in database                |
| OTP verification          | Hardcoded / local      | Backend verified                  |
| Booking persistence       | localStorage           | Supabase / PostgreSQL             |
| Payments                  | Demo                   | Razorpay UPI                      |
| Notifications             | None                   | SMS / WhatsApp                    |

## Step-by-step Implementation Order

### Phase 1 – Foundation (Week 1)
1. Create Supabase project
2. Run `supabase-schema.sql`
3. Enable Phone Auth (or Email for testing)
4. Connect frontend to Supabase client

### Phase 2 – Core Tracking (Week 2)
1. Driver app: request location permission
2. Send GPS coordinates every 8–10 seconds to `trips` table
3. Receiver screen: subscribe to realtime updates on the trip
4. Show live marker on map (Google Maps or Mapbox)

### Phase 3 – Booking + Status (Week 3)
1. Create parcel with auto-generated `tracking_id`
2. Status machine:  
   `booking_confirmed → awaiting_pickup → parcel_onboard → in_transit → arrived → delivered`
3. Generate and store delivery OTP
4. Driver enters OTP → mark as delivered

### Phase 4 – Payments & Notifications (Week 4)
1. Razorpay order creation
2. Webhook to mark payment as paid
3. Send SMS/WhatsApp on status change

## Key Realtime Pattern (Supabase)

```js
// Receiver side – listen to trip location
const channel = supabase
  .channel('trip-location')
  .on(
    'postgres_changes',
    {
      event: 'UPDATE',
      schema: 'public',
      table: 'trips',
      filter: `id=eq.${tripId}`
    },
    (payload) => {
      const { current_lat, current_lng } = payload.new;
      updateBusMarker(current_lat, current_lng);
    }
  )
  .subscribe();
```

Driver side simply updates the trip row:

```js
await supabase
  .from('trips')
  .update({
    current_lat: position.coords.latitude,
    current_lng: position.coords.longitude,
    last_location_at: new Date().toISOString()
  })
  .eq('id', tripId);
```

## Browser GPS (for prototype testing)

You can test real GPS in the browser (Chrome / mobile Safari):

```js
navigator.geolocation.watchPosition(
  (pos) => {
    const { latitude, longitude } = pos.coords;
    // send to Supabase
  },
  (err) => console.error(err),
  { enableHighAccuracy: true, maximumAge: 5000, timeout: 10000 }
);
```

**Limitation:** Background tracking is unreliable in browsers.  
For production drivers you will eventually need a simple React Native / Flutter app.

## Security Notes

- Never expose service role key in frontend
- Use Row Level Security (already started in schema)
- Validate OTP only on the server
- Rate-limit location updates
